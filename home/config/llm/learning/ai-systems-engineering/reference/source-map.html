AI Systems Engineering Source Map

Use this map to decide which source to open for each production concern. The goal is not to memorize every framework. The goal is to know which engineering question each source helps answer.

Production Questions

Agent runtime

How does the workflow run, pause, resume, and carry state?

Start with LangGraph for durable execution, persistence, human-in-the-loop, and memory concepts.

Tool boundary

What can the model ask the application to do?

Start with OpenAI function calling for JSON-schema tool contracts, strict mode, and application-owned execution.

Integration surface

How does this AI system connect to external systems cleanly?

Start with MCP for standard resource, prompt, and tool exposure across clients and servers.

Operational proof

How do we know it works and stays working?

Start with OpenAI evals and OpenTelemetry GenAI conventions for regression checks, traces, metrics, latency, and token/cost visibility.

Source Checklist

OpenAI Agents SDK guide

Use when designing agent definitions, orchestration, guardrails, state, integrations, observability, and workflow evaluation.

OpenAI Function calling guide

Use when designing tool schemas and deciding which actions stay under application control.

OpenAI Evals guide

Use when converting expected behavior into datasets, graders, and regression checks.

MCP introduction and MCP specification

Use when building or assessing standard connections between AI clients and external systems.

LangGraph overview and persistence docs

Use when a workflow needs state, resumability, memory, fault tolerance, streaming, or human review.

OpenTelemetry GenAI semantic conventions

Use when naming traces, spans, metrics, events, exceptions, agent activity, and MCP activity in a vendor-neutral way.

Rule of thumb: a Phase 2 AI feature calls a model. A Phase 3 AI system can explain how the model is constrained, measured, interrupted, resumed, observed, and replaced when it fails.
