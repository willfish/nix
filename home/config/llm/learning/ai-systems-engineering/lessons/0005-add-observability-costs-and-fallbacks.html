Add Observability, Costs, and Fallbacks

A system you cannot inspect is a system you cannot own. AI systems need traces across model calls, tool calls, retrieval, approval pauses, retries, failures, latency, and cost.

The Win

You will define the operational sheet for your system: traces, metrics, logs, cost and latency budgets, alert conditions, and fallback behavior.

Primary Sources

  • OpenTelemetry GenAI semantic conventions pointer for the current canonical location.
  • OpenTelemetry GenAI docs directory for spans, metrics, events, exceptions, agent spans, and MCP vocabulary.
  • OpenAI Agents SDK guide for tracing and observability concepts around agents.

Operational Questions

Trace

Can you reconstruct the run across model choice, prompt/context, retrieval, tool calls, approval pauses, retries, and final output?

Measure

Can you see success rate, eval pass rate, tool error rate, token use, latency, cost, and human review volume?

Fallback

Can the system degrade: smaller model, cached answer, search-only response, human queue, or explicit failure?

Exercise: Write the Ops Sheet

Fill this in for your workflow. Keep it specific enough to implement in logs, traces, metrics, and alerts.

A strong ops sheet makes the harness visible, not just the answer.
