Build Evals and Guardrails

Prompt quality is not an operating claim. Evals and guardrails turn expected behavior, unsafe behavior, and regression risk into something you can inspect repeatedly.

The Win

You will create an eval matrix for your agent workflow: success cases, edge cases, adversarial cases, tool-use checks, and guardrail checks.

Primary Sources

  • OpenAI Evals for datasets, graders, and regression-oriented evaluation.
  • OpenAI Agents SDK guide for agent guardrails and workflow evaluation.
  • OpenAI Function calling for checking whether model-selected tool arguments match strict schemas.

Eval Types

Golden path

Representative cases that should pass when the system is working as intended.

Edge cases

Ambiguous, incomplete, high-volume, or conflicting inputs that reveal workflow brittleness.

Adversarial cases

Inputs that try to bypass tool boundaries, approvals, data limits, or output policy.

Regression checks

Small repeatable tests that protect important behavior whenever prompts, tools, models, or retrieval change.

Exercise: Write the Eval Matrix

Write at least eight cases. Each case needs an input, expected behavior, grader/check, and guardrail relevance.

A strong eval matrix names expected behavior and failure behavior.

Portfolio Translation

Weak: I improved the prompt until it worked.

Strong: I built a regression suite covering golden paths, adversarial tool-use attempts, approval gates, and fallback behavior, then used it to compare prompt and model changes.
