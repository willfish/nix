# PR Slack Roundups

Use this when summarising pull requests for Slack.

## Gathering PRs

- Use GitHub MCP or `gh` to gather PR titles, URLs, branches, status, and review
  state.
- Prefer repository/PR data over browser scraping.
- Use Slack MCP only to read relevant channel context or post after explicit
  user approval.

## Drafting Style

- Draft one concise line per PR.
- Include the PR link and enough context for a teammate to decide whether they
  need to act.
- Mention blockers, review asks, or deployment risk only when relevant.
- Use `will-voice` when drafting text that should sound like Will.

## Posting Rule

Draft Slack messages for review by default. Post only when the user explicitly
asks you to send.
